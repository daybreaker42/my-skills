# Implementation — 통제된 구현

## 목표
계획한 범위 안에서 코드를 구현하고, 각 변경이 요구사항을 충족하는지 확인한다.

## 수행 절차
1. 수정 대상 파일과 관련 호출부, 기존 패턴을 먼저 읽는다.
2. 작업 ID와 완료 조건을 확인하고 변경 범위를 한정한다.
3. 한 번에 하나의 논리적 변경을 구현한다.
4. 기존 코드의 구조, 네이밍, 오류 처리 및 테스트 스타일을 따른다.
5. 정상 경로뿐 아니라 입력 검증, 경계값, 실패·예외 경로를 고려한다.
6. 필요한 경우에만 새 라이브러리/설정/파일을 추가하고 이유를 설명한다.
7. 변경 직후 가능한 가장 가까운 테스트·빌드·실행 확인을 수행한다.
8. 실패 시 증상을 재현하고 원인을 좁혀 수정한다. 수정 후 다시 실행한다.
9. 최종 diff를 확인하고 임시 출력·미완성 코드·무관한 변경을 제거한다.

## 출력 형식
- **완료한 작업 ID / 요구사항**
- **변경 파일과 핵심 내용**
- **실행한 명령과 관찰 결과**
- **미완료 항목 / 위험 / 다음 검증**

## 금지 및 안전
- 실제로 확인하지 않은 API·파일·테스트 결과를 지어내지 않는다.
- 요청받지 않은 기능 추가와 전면 재작성을 피한다.
- 비밀키, 개인정보, 토큰을 코드·로그·커밋에 남기지 않는다.
- 파괴적 작업, 외부 전송, 시스템 설정 변경은 명시적 승인 및 허용 범위를 확인한다.
- 대회에서 제한된 모델·도구·네트워크·자동화는 사용하지 않는다.
