# Verification — 독립 검증 및 회귀 테스트

## 목표
**구현했다**와 **검증됐다**를 구분한다. 실행 근거를 사용해 요구사항 충족 여부를 판단한다.

## 수행 절차
1. 명세의 각 요구사항을 관찰 가능한 기대 결과로 변환한다.
2. 검증 순서를 정한다: 구문/빌드 → 핵심 정상 경로 → 경계값 → 잘못된 입력 → 실패 경로 → 회귀 → 요구된 성능.
3. 저장소에 이미 정의된 테스트/실행 명령을 우선 사용한다.
4. 테스트 명령, 종료 코드, 실제 출력, 기대 결과를 기록한다.
5. 실패하면 재현 조건을 고정하고 원인을 추적한다. 테스트를 삭제하거나 예외를 숨겨 통과시키지 않는다.
6. 수정 후 실패한 테스트와 관련 회귀 테스트를 재실행한다.
7. 최종 diff에서 불필요한 변경, 디버그 출력, 누락된 오류 처리를 확인한다.
8. 요구사항별로 `PASS / FAIL / PARTIAL / NOT RUN`을 판정한다.

## 출력 형식
| 요구사항 | 검증 방법 | 실제 결과 | 판정 | 근거 |
|---|---|---|---|---|

마지막에 **통과 항목 / 실패·수정 항목 / 미실행 사유 / 잔여 위험 / 제출 가능 여부**를 제시한다.

## 엄격한 규칙
- 실행하지 않은 테스트를 통과했다고 말하지 않는다.
- 일부 테스트 통과를 전체 정확성의 증명으로 확대하지 않는다.
- 사용한 샘플 데이터와 실제 데이터의 차이를 명시한다.
- 근거 없는 `완벽`, `100% 정확` 등의 표현을 쓰지 않는다.
