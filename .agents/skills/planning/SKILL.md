# Planning — 작업 분해 및 실행 계획

## 목표
선택한 해결안을 작고 검증 가능한 작업으로 나누어 **계획 → 실행 → 확인**의 루프를 만든다.

## 수행 절차
1. 현재 저장소 구조, 실행 명령, 기존 코드, 테스트 및 의존성을 먼저 확인한다.
2. 요구사항과 코드 위치를 연결한다. 실제로 확인한 경로·함수만 기재한다.
3. 가장 작은 동작 가능한 결과(MVP)를 정의한다. 부가 기능은 분리한다.
4. 작업을 작은 단위로 분해하고 우선순위와 선행 조건을 표시한다.
5. 각 작업에 **완료 조건**과 **검증 방법**을 붙인다.
6. 실패 위험이 큰 가정은 초기에 작은 프로토타입/테스트로 확인한다.
7. 전체 제한 시간이 주어지면 분석, 구현, 검증, 최종 확인에 시간을 배분하고 검증 시간을 확보한다.
8. 범위가 변경되면 계획과 완료 조건을 함께 수정한다.

## 출력 형식
| ID | 작업 | 우선순위 | 선행 작업 | 완료 조건 | 검증 방법 |
|---|---|---|---|---|---|

추가로 **MVP 범위 / 후순위 범위 / 핵심 위험 / 지금 할 일**을 간단히 제시한다.

## 원칙
- 작업은 가능하면 각각 독립적으로 확인할 수 있게 만든다.
- 불필요한 재설계, 의존성 추가, 대규모 리팩터링을 피한다.
- 시간 제한에서 필수 기능 완성 및 테스트를 미관·부가기능보다 우선한다.
- 사소한 변경은 짧은 체크리스트만 사용한다.
